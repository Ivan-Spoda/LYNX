## 1. Frequency Splitter

**What LYNX assumes** (`FlEffects.cpp` `frequencySplitter`/`frequencySplitterBand`): bus 1 = low,
2 = mid (or high in 2-band mode), 3 = high; slope always 24 dB/oct Linkwitz-Riley; levels in
hundredths of a dB.

### 1.1 Outputs and buses **[DECOMP + DOC]**

- The engine (`processReplacing` `FUN_1801e56d0` → `FUN_1801e5c90`) produces **4 stereo pairs**, in this order:
  **0 = low × low send level, 1 = mid × mid send level, 2 = high × high send level,
  3 = "Summed Out" sum = low·level(L) + mid·level(M) + high·level(H)** (engine parameters 11…13,
  "Low/Mid/High Level (Summed Out)").
- **2-band mode** (engine flag `+0x115`; parameter "Number of Bands" < 0.5): only one crossover (the frequency
  "Low/High Freq"); the **mid pair is written as zero** and the high stays on **pair 2**. That is: in 2 bands the
  high does **not** move into the mid's place.
- **3-band mode:** crossover 1 at f1 → (low, rest); the rest goes through crossover 2 at f2 → (mid, high);
  the low goes through a third crossover at f2 and the two halves are summed back (phase compensation of the
  low to match the other branches).
- The Delphi *wrapper* (`FUN_007423b0`) sends pair 3 (sum) to the plugin's **main output** and each band i
  (0 low, 1 mid, 2 high) to the **band's own send destination**, stored in fields `P+0x214`,
  `+0x218`, `+0x21C`. That destination is per band (each band has its own), and is only used when the value is > 0.
  The send is done by the host's send *buffer* function (host vtable `+0x128`, the same one used by the
  Stereo Shaper). For the band sends, the manual says: "Sends are Pre-Fader to the destination Mixer Track" and
  "The 'MAIN OUT' and 'SENDS' carry the same signals" **[DOC `…/plugins/Frequency%20Splitter.htm`]**.
- **Where the destinations live in state `0xD5`** **[DECOMP `FUN_0073fac0`]**: `u32 version (4)` + **0x44 bytes
  = 17 × i32 copied to `P+0x1DC`**. So word *w* (counting the version as 0) is `P+0x1DC+4(w−1)`, and
  **words 15, 16 and 17 are the send destinations of the low, the mid and the high**. Then come `i32` (value
  of a UI control), `i32` (discarded on read), two `i32` of UI bits, an options byte (bits 0…5:
  UI, `P+0x254`, `P+0x255`, `P+0x28C`, `P+0x28D`, `P+0x2A0`) and, in v ≥ 3/4, 6 more UI `i32`.
- **Consequence for LYNX:** in a Patcher graph, the splitter's output bus is the **destination
  number stored for the band**, not a fixed position. Bus k carries band i whose destination
  (word 15+i) equals k; bus 0 carries the sum. If the three destinations are 1, 2 and 3 (which the demo
  graphs use), then 1 = low, 2 = mid and 3 = high. **In 2 bands, the mid bus is silent.** The
  correspondence "destination value = Patcher bus number" is made by the host (FL.exe), which was not
  decompiled: it is consistent with the round 14 data, but **not confirmed** by code.

### 1.2 Slopes (combo 0…7) **[DECOMP `FUN_1801e6440`, `FUN_1801e8190` + DOC]**

The parameter text is "%i dB" with the table `{6, 12, 18, 24, 36, 48, 72, 96}`, indexed by
`⌊v_normalizado / 0.125⌋`. Manual: "Choose between -6 and -96 dB/Octave slopes" **[DOC]**. Filter
design per value:

| combo | dB/oct | Structure **[DECOMP]** |
|---|---|---|
| 0 | 6 | 1 first-order section (complementary LP/HP) |
| 1 | 12 | 1 biquad with Q = 0.5 and **HP polarity inverted** (= 2nd-order Linkwitz-Riley) |
| 2 | 18 | own all-pass-based structure (alternative path `+0x515` of the crossover) |
| 3 | 24 | 2 cascaded biquads Q = 0.7070 (= **Linkwitz-Riley 4**: Butterworth 2 squared) |
| 4 | 36 | 3 biquads Q = 0.5412 / 1.3066 / 0.7070, HP inverted |
| 5 | 48 | 4 biquads Q = 0.5412 / 1.3066 / 0.5412 / 1.3066 (= **LR8**: Butterworth 4 squared) |
| 6 | 72 | 6 biquads (Butterworth 6 Qs: 0.5176 / 0.7071 / 1.9319, twice) |
| 7 | 96 | 8 biquads (Butterworth 8 Qs: 0.5098 / 0.6013 / 0.9000 / 2.5629, twice) |

That is: **the even modes are Linkwitz-Riley** (Butterworth squared). LYNX is right for combo 3 and
wrong for the others. There is also the "Linear phase / FFT" mode (parameter "Filter Mode": Normal/FFT); the
manual: "Normal … Near zero-latency Infinite Impulse Response (IIR) filters"; linear phase with latency of
"between 12 and 290 ms" **[DOC]**. The FFT mode was not detailed.

### 1.3 Frequencies and levels **[DECOMP `FUN_1801e6670`, `FUN_1801e6d00` + DOC]**

- Frequency: **`f = 30 · 2^(9.0589·x)` Hz** (x = normalised value 0…1; 30 Hz…16 kHz). Equivalent to the formula
  `30·(16000/30)^x` used by LYNX. Manual: "between 30 Hz and 16 kHz" **[DOC]**.
- Level (send and sum), x normalised: **linear gain = 2x for x < 0.5; = 1 + 13.8866·(x − 0.5) for x ≥ 0.5**
  (0 → muted, 0.5 → 0 dB, 1 → +18.0 dB). Manual: "+18 dB to -∞ (muted)" **[DOC]**. The `.flp` word in
  hundredths of a dB (round 14) is the form the *wrapper* stores; the dB ↔ x conversion was not re-read here.
- Per-band mute/solo zero/isolate the gains (`FUN_1801e6d00`, fields `+0x1144…+0x114F`).

## 2. Fruity Stereo Shaper inside Patcher

**What LYNX assumes:** only the L/R matrix (words 1…4). Question: what comes out on bus 1.

**[DECOMP `FUN_006cf460`, `FUN_006ce390` + DOC]**

- State `0xD5` = `i32 version` + **8 × i32** at `P+0x120…0x13C` = parameters 0…7: 0…3 matrix (R→L, L, R,
  L→R; ×12800 = 1.0 as already in LYNX), 4 *delay*, 5 phase, **6 = destination of the "In/Out Difference" signal**
  (`P+0x138`), **7 = effects order (pre/post)** (`P+0x13C`).
- In the render: if the destination (parameter 6) is > 0, the input is copied before processing; after
  processing, **input − output** is computed and that signal is **added to the send *buffer*** of the chosen
  destination (same host function `+0x128` as the Frequency Splitter). The **main output (bus 0)** is the
  processed signal (matrix + effects).
- Manual: "sends a 'difference' signal to the selected sidechain Mixer track … (Input - Output = Difference)";
  preset "aMid - Side splitter": "An 'adapted' Mid signal remains on the host Mixer track and a Side signal is
  sent to the IN/OUT Difference track"; "Mid = (L+R)/2", "Side = (L-R)/2" **[DOC `…/plugins/Fruity%20Stereo%20Shaper.htm`]**.
- **For LYNX:** bus 0 = matrix output; **bus k (k = value of parameter 6) = input − output**.
  In the M/S preset, the matrix leaves only the *mid* on bus 0 and the difference (the *side*) comes out on the
  destination's bus. Same caveat as §1.1: the equality "destination k = Patcher bus k" is made by the host and was not
  read in FL.exe (**not confirmed** by code; consistent with the round 14 data).

## 3. Fruity Balance and Fruity PanOMatic — volume

**What LYNX assumes:** 0…320, 256 = 0 dB, curve `(11^x − 1)/10`, x = v/256.

**Confirmed [DECOMP + DFM]:**

- DFM `TSynthEditorForm`: Balance `VolWheel` **Max 320, Value/Default 256**, `PanWheel` −128…128 (0);
  PanOMatic `VolWheel` **Max 320, Default 256**, `PanWheel` 0…256 (128), LFO amount 0…128 (64), LFO speed
  0…55000 (27500), shape Sine/Triangle/Square, target OFF/PAN/VOL.
- PanOMatic (`FUN_006c6650`, parameter 1): **gain = (11^(v/256) − 1)/10** (the `ln 11` is computed at
  initialisation `FUN_005e1bc0`); v = 256 → 1.0 exactly.
- Balance (`FUN_006beaa0`, parameter 1): x = v/320; **gain = (11^(1.25·x) − 1)·(1/(10·cos(π/4)))** × balance
  law. Since 1.25·v/320 = v/256, it is the same curve; the factor `1/cos(π/4)` cancels the `cos/sin(π/4)` of the pan
  law at centre, so **v = 256 → 0 dB**, v = 320 → **+5.59 dB**, v = 128 → −12.7 dB.
- Balance law (same function): angle `(b/128 + 1)·π/4` (b = −128…128) gives the L/R gains via sine/cosine,
  multiplied by `1 − 0.5·|sen(π·|b/256|)|`; when b ≠ 0 there is also a cross term (the channel on the opposite
  side receives the difference of the two gains) — this is the manual's "true panning … by mixing left and right channels"
  **[DOC `…/plugins/Fruity%20Balance.htm`]**.

**Conclusion: the LYNX assumption is correct** for the volume of both plugins.

## 4. Fruity X-Y Controller — tension curve

**What LYNX assumes:** `level^(2^(−2·tension))`.

**Confirmed [DECOMP `FUN_006c6360` (tension), `FUN_006c6d90` (*tick*, VMT+14)]:**

- Tension t = −128…128 → sign s = sign(t) and **k = (1001^(|t|/128) − 1)·0.1** (t = 128 → k = 100; 64 → 3.06;
  32 → 0.46).
- The smoothed position p (0…1) of each axis becomes:
  - s = 0: `y = p` (straight line);
  - **s > 0: `y = 1 − ((k + 1)^(1 − p) − 1)/k`** (concave: rises fast at the start);
  - **s < 0: `y = ((k + 1)^p − 1)/k`** (convex: rises slowly).
- Output = `min + y·(max − min)` (integers 0…65536, clipped to the range), published as control
  **axis 0 = output 0 (X), axis 1 = output 1 (Y)** (the index passed to the host is the axis index).
- Manual: "Tension (TNS) … alter the shape of the curve used to map the coordinate values to the controller
  values" **[DOC `…/plugins/Fruity%20X-Y%20Controller.htm`]**.

**The LYNX formula is wrong** (it is a power; FL's is a normalised exponential). Same family as the
Peak Controller tension (§5).

## 5. Fruity Peak Controller

**What LYNX assumes:** outputs 0/1/2 = peak/LFO/product; decay to −60 dB = 20/speed s; attack not modelled.

### 5.1 Output indices **[DECOMP `FUN_006fd830` + `FUN_006fdbc0` + DOC]**

The output name (dispatch 7 = "output control name") comes from the table `{"Peak+LFO", "Peak", "LFO"}`:
**output 0 = Peak + LFO (sum), 1 = Peak, 2 = LFO**. In the *tick* the three are computed like this (internal scale
0…2^30 = 0…1, clipped to 0…1): `peak_out`, `lfo_out` and **`peak_out + lfo_out`**. Manual: "Peak Ctrl -
Peak+LFO - The combination (sum) of the above two automation signals" **[DOC `…/plugins/Fruity%20Peak%20Controller.htm`]**.
→ **LYNX has the order and the nature of output 0 wrong** (it is not a product).

### 5.2 Peak output formula **[DECOMP `FUN_006fcef0`, `FUN_006fdbc0`]**

With the round 14 parameters (Base 0…65536, Amount −256…256, Tension −128…128, Decay 5…128):

- `a = sign(A)·(6^(|A|/256) − 1)·0.4` (A = 256 → +2.0 = 200 %; manual: "values from -200% … to 200%" **[DOC]**).
- Tension: `k = (1001^(|T|/128) − 1)·0.1`; if T ≠ 0, the amount is divided by k.
- Shape (p = peak detector, §5.3): T = 0 → `y = p`; **T > 0 → `y = k − ((k + 1)^(1 − p) − 1)`**;
  **T < 0 → `y = (k + 1)^p − 1`**; and then `peak_out = Base/65536 + a·y/k` (= `a·p` with T = 0).
  It is exactly the X-Y curve (§4) multiplied by `a`.
- LFO: base 0…65536, `a_LFO = sign·(6^(|v|/256) − 1)·0.2` (max. ±1.0 = 100 %; manual: "-100% … to 100%"
  **[DOC]**), same tension; shape table indexed by phase.

### 5.3 Detector, attack and decay **[DECOMP `FUN_006fda30`, `FUN_006fd0e0`, `FUN_006fc6d0`]**

- **Instantaneous attack:** on each audio block, `p = max(p, absolute peak of L and R in the block)` (linear value,
  no smoothing and no limit at 1.0). There is no attack control (the manual lists none).
- **Linear decay in musical time:** on each host *tick* (method `NewTick`, VMT+14), `p ← p − d`, clipped
  at 0, with **`d = (10001^(D/128) − 1)·0.0192 / PPQ`** (D = 5…128). The divisor is field `+0x188`, written by
  dispatch 14 with the 3rd integer of the received record (time signature: steps per bar, steps per
  beat, **PPQ**). So, per **quarter note**, p drops `(10001^(D/128) − 1)·0.0192`:

  | D | decay per quarter note | time to fall from 1.0 to 0 |
  |---|---|---|
  | 5 | 0.0083 | 120 quarter notes |
  | 33 | 0.187 | 5.3 quarter notes |
  | 66 (default) | 2.20 | 0.45 quarter note |
  | 100 | 25.6 | 0.04 quarter note |
  | 128 | 192 | 0.005 quarter note |

  (It is assumed, as in the FL SDK, that `NewTick` is called once per PPQ *tick*; the code only shows the
  division by PPQ.) **The LYNX assumption "20/speed s to −60 dB" does not match**: the decay is linear (not
  exponential) and proportional to the tempo.
- LFO speed (`FUN_006fd180`): period = `(1001^(v/65536) − 1)·0.128` quarter notes (v = 32950 → 4
  quarter notes = 1 bar of 4/4; 65536 → 128 quarter notes).

## 11. Fruity DX10 — FM depth

**What LYNX assumes:** index (cycles of phase deviation per unit of modulator) = `2·p²`.

**Confirmed [DECOMP `FUN_00735760`, `FUN_00735e30`, `FUN_007364a0`]:**

- The carrier phase is a variable `φ` in **half-cycle units** (period 2: it is wrapped into ±1 and the
  waveform is the mda-style polynomial `φ + φ³·(r·(φ² − 1) − 1)`, r = "Waveform"). Per sample:
  **`φ += D + L₁·M₁ + L₂·k₂·M₂`**, where D is the carrier increment and `Mᵢ` is the sine of modulator i (host
  16384-point table). **It is true FM** (modulation added to the increment), not PM.
- **Carrier increment:** `D = 8.1758·2^(oct+1)·2^(note/12)/fs` → carrier at
  **`f_c = D·fs/2 = 8.1758·2^(note/12)·2^oct` Hz** (oct = −3…+3 from "COARSE"; 0 = tuning of the MIDI note).
- **Frequency of modulator i:** phase increment `(coarse + fine)·2^30·D` in 2^32 → **`f_m = R·f_c/2`**
  (R = coarse+fine ratio from round 10). That is, with R = 1 the modulator sounds an octave **below** the
  carrier, according to the code.
- **Modulator level:** `L = 0.0002·p²·(44100/fs) · min(2^(note/12), 50) · (S·(V − 64) + 64)` with p = "Init"
  (and the same for "Sustain"), S = velocity sensitivity (0…1) and V = velocity mapped through the velocity
  curve (only with S = 0 is the factor the constant 64). The level goes from Init to Sustain with the coefficient of
  "Time".
- **Equivalent modulation index** (peak deviation ÷ modulator frequency), putting it all together and with S = 0:
  - peak frequency deviation = `L·fs/2` Hz;
  - **β (rad) = (L·fs/2)/f_m = 0.0002·64·44100·p² / (R·2^(oct−1)·8.1758) ≈ `69.0·p² / (R·2^oct)`** for notes
    up to ~67.7 (above that the factor `min(·, 50)` reduces β);
  - in **cycles of phase deviation**: `β/(2π) ≈ 11.0·p²/(R·2^oct)`.
  The LYNX assumption `2·p²` underestimates the depth by ~5×, and the DX10 FM is relative to `f_m = R·f_c/2`.
- The second modulator enters **in parallel** (added to the same carrier increment), with its own
  level `k₂·L₂` **[DECOMP]**.
- "Mod Thru" (p12): mixes `0.25·p²` of the modulator into the output (round 10; the render adds `thru·M₁` to the output).
- Manual: only describes the controls; does not mention an index **[DOC `…/plugins/Fruity%20DX10.htm`]**.

## 13. Low Lifter — the harmonic "enhancement"

**What LYNX assumes:** `+0.25·preBoost` dB on a *low shelf*.

**Confirmed [DECOMP `ildsp_x64.dll` `FUN_180177a80`, `FUN_180177f50` + DOC]:** the DSP is not in the plugin
DLL: `Low Lifter_x64.dll` loads `LowFreqEnhancer_CreateInstance` from `Shared/ildsp_x64.dll`, whose class
`ILRDLowFreqEnhancer` was generated by Faust from `lowFreqEnhancementChebyshev.dsp`.

- Controls (Faust UI ranges): Dry/Wet 0…1; **Low Gain −120…+18 dB**; **Pre Gain 0…18 dB**; **Slope
  −60…0 dB**; Diffusion Mix 0…1, Depth −0.99…0.99; **High Gain −120…0 dB**; **Crossover 20…120 Hz** and **Low
  Cut 20…120 Hz** (log scale); switches Multiband, Lookahead, Invert Polarity, Low/High Switch.
- **Harmonic generator (per band):**
  1. the low-band signal is multiplied by `g = 10^(PreGain/20)` (and by −1 if *Invert Polarity*);
  2. a peak follower with *lookahead* (read delay, chain of maxima with hold and four release
     stages) gives the envelope E, **bounded from below at 1.0**: `u = x_delayed / max(1, E)` — this is the
     manual's "lookahead limiter [that] will prevent these boosted frequencies from exceeding 0 dB";
  3. **Chebyshev polynomials up to 3rd order:** with `a = 10^(Slope/20)` and `b = 10^(Slope/10) = a²`,
     **`y = [u + a·T₂(u) + b·T₃(u)] / (1 + 2a)`**, where `T₂(u) = 2u² − 1` and `T₃(u) = 4u³ − 3u`;
  4. `y` goes through a 1st-order filter (removes the DC of T₂) and on to the diffuser/mix.
  For a sinusoid of amplitude A ≤ 1 (after the pre-gain), T₂ and T₃ produce the **2nd harmonic with amplitude
  `a·A²`** and the **3rd with `b·A³ = a²·A³`** (relative, before the 1/(1+2a) normalisation) — i.e. "Slope" is the
  drop in dB per harmonic order and "Pre Gain" controls how much of the band enters the non-linear region.
- The rest of the chain (crossover, band gains, 2nd-order *low cut*, all-pass diffuser, dry/wet) was already
  described in round 15 §5. Manual: "dynamically adds harmonics to bass frequencies ... psychoacoustic
  principle"; "Slope - Harmonics decay slope in dB"; "Low cut - Cutoff of a final-stage second-order highpass
  filter" **[DOC `…/plugins/Low%20Lifter.htm`]**.
- **Correct approximation for LYNX:** instead of `+0.25·preBoost` dB, apply to the band below the crossover a
  *waveshaper* `y = (u + a(2u² − 1) + a²(4u³ − 3u))/(1 + 2a)` with `u = clamp(g·x, −1, 1)` (FL's limiter
  is dynamic; the `clamp` is the part LYNX can reproduce without *lookahead*), followed by a DC
  high-pass and the mix with the band gains.

## 15. Love Philter — extra items from round 16 (coordinator request)

### 15.1 Unit factor `k` (`+0xC4`) and the SVF formula **[DECOMP]**

- `k` is copied in `FUN_0085d5a0` from field `+0x20` of the plugin's rate object. That object receives, in
  `FUN_00854e20`, **host rate × oversampling factor** (`+0x168C`, obtained from the oversampler via the
  `DQOverSelect` option, doubled with HQ), and its rate method (`FUN_0062b030`) writes `+8 = taxa` and
  **`+0x20 = 44100/taxa`**. So **`k = 44100 / fs_interno`**, as round 16 assumed.
- **"Chocolate" SVF (type 0):** the processing (`FUN_006257c0`, via function pointer `0x8d36d0`) is the
  Chamberlin SVF: `LP += f·BP; HP = in − LP − q·BP; BP += f·HP` (L, B and H come out of the three *buffers* and are summed with
  the L/B/H gains). The coefficient is **`f = 2·sen(w)`**, `w = min(0.625, (x + 0.005)·k)`, `x = (51^c − 1)·0.0159`
  (sine = Delphi's `Sin` routine, `FUN_0040bb50`). Since in Chamberlin `f = 2·sen(π·fc/fs)`,
  **`fc = (x + 0.005)·44100/π` Hz, independent of oversampling**, up to the ceiling `w = 0.625`, which equals
  **`fc_max = 0.625·fs_interno/π`** (8,773 Hz at 44.1 kHz without oversampling; 17.5 kHz with 2×). Values without
  ceiling: c = 0 → 70 Hz; 0.25 → 443 Hz; 0.5 → 1.44 kHz; 0.75 → 4.1 kHz; 1 → 11.2 kHz.
- The damping `q` (`+0xC` of the stage) comes from `d = 1 − 0.9·r` (round 16); there is a path that divides it by
  `f` and multiplies by `k` before processing (option not identified).

### 15.2 *Alternate* modes (4 and 5) **[DECOMP `FUN_0085d5a0`, `FUN_00859100`]**

- No. of stages: `modo − 1` in `+0xB4`; if `modo − 1 > 2` (modes 4/5) the *alternate* flag (`+0xB8`) is set and
  2 is subtracted → **mode 4 = 2 stages, mode 5 = 3 stages** (the same numbers as "dual"/"triple").
- With *alternate*, after computing each stage the frequency variable x (before the *offset*) is raised
  to an exponent from table `0x8d1e4c` indexed by the number of stages: **E = 0.5 for 2 stages, 0.75 for 3**.
  The stages are computed from last to first, so the cutoffs are `x, x^E, x^(E²)` (x < 1 → the
  following stages become **higher**). Applies to the SVF and to the biquad families.
- In multi-stage, the resonance/width is raised to `1/N` (`+0xBC = 1/(N)`; in Mango, another formula).

### 15.3 Mod Y → volume **[DECOMP render `FUN_0085aa10`]**

- X and Y (0…1024) are smoothed and used as **integer indices (0…1024) into 1025-point tables** that
  sample the curve of each map. For each articulator: `out = base`; for each present map (X, Y,
  envelope follower × depth), according to the articulator's integer combination mode:
  **mode 0: `out ·= map(·)`**, mode 1: `out += map(·)`, others: `out ·= 2·map(·)`. Then the
  articulator's virtual method `+0x38` is called (envelope/LFO; not decompiled).
- The unit volume applied at the output is **`VOL_unit · volume_articulator_output`** (call
  `FUN_00616620(pan = PAN + 2·art_pan, vol = VOL · art_vol)`), and the pan is **added** (`2·art_pan`).
- Therefore, if the volume articulator is in mode 0 (multiplicative) with the other maps neutral (1.0),
  **the unit gain is multiplied linearly by `mapaY(y)`** — with the line (0,0)→(1,1), gain = y.
  **Caveats:** which value of the integer mode field corresponds to the "unipolar" stored in the `.flp` and what the
  method `+0x38` does with the envelope/LFO disabled **were not confirmed**.
